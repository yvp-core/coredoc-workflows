# Jira work note

Use this only as the body of an explicitly authorized Jira comment. Keep it
compact enough for a reviewer to understand the intended work without reading a
second specification. Do not copy the issue description.

## What

State the intended outcome in one or two sentences.

## Why

Name the problem or acceptance criterion that makes the change necessary.

## Scope

Name the affected repository surfaces and the important non-goals. Link an
authoritative design only when one already exists and the link was observed.

## Check

State how the result will be verified and where a developer or QA engineer
should begin checking it.
